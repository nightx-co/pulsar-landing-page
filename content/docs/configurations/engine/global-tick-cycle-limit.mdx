title: Global Tick Cycle Limit
description: Set a maximum ceiling on total tick executions across all queues per cycle.

The `cycleTickLimit` property sets a global cap on the total number of tick executions allowed across all queues within a single execution run.

Once the cumulative tick count reaches this threshold, the engine cleanly terminates the current cycle and triggers a self-invocation restart.

## Usage

Pass `cycleTickLimit` inside the `engine` configuration object:

```ts
const engine = new Pulsar({
  runtime: PulsarRuntime.SERVERLESS,
  engine: {
    cycleTickLimit: 10, // [!code highlight]
  },
});
```

---

## Configuration Reference

- **Default:** `Infinity` (No global limit)

---

## Execution Behavior by Concurrency Mode

How `cycleTickLimit` distributes ticks across your queues depends directly on your configured `tickConcurrency`.

### Sequential Mode (`tickConcurrency: "sequential"`)

Ticks are processed strictly one by one in predictable order. With 10 queues and `cycleTickLimit: 10`, each queue executes exactly 1 tick before the engine terminates the cycle.

<Mermaid
  chart="
graph LR;
  Q1[Queue 1: Tick 1] --> Q2[Queue 2: Tick 1];
  Q2 --> Q3[Subsequent Queues: 8 Ticks];
  Q3 --> Terminate[Global Limit Reached: Terminate & Restart];
"
/>

### Parallel Mode (`tickConcurrency: "parallel"`)

Ticks across queues execute concurrently without strict round-robin fair distribution. Fast-completing queues may process multiple ticks while slower queues are still finishing their first.

<Mermaid
  chart="
graph TD;
  Engine[Engine Run - Limit 10 Ticks] --> Q1[Queue 1: Tick 1 -> Tick 2];
  Engine --> Q2[Queue 2: Processing Tick 1];
  Engine --> Q3[Queue 3: Tick 1 -> Tick 2 -> Tick 3];
  Q1 --> Limit[Cumulative 10 Ticks Reached];
  Q2 --> Limit;
  Q3 --> Limit;
  Limit --> Terminate[Terminate Cycle & Restart];
"
/>

<Callout type="info">
`cycleTickLimit` tracks **total cumulative ticks** across the engine instance, regardless of which individual queues executed them.
</Callout>
